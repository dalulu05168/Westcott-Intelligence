# 人物口吻引擎：65人Humanizer逐人匹配

## 真实来源与审批
每轮先读取正式65人身份 `../characters/final-identity-65.json`、选定人物profile、`../voice-management/voice-index-2026-10-21.json` 中该人物的 `voice.evidence`，并核对最新已采用Google Docs对应日页签。
身份字段是用户批准事实；候选 `voice_status=CREATIVE_DRAFT_NOT_USER_APPROVED`、`approved_style=false` 不代表正式性格批准。
本地网页批准的数据只有用户导出后并经明确审阅，才可同步为仓库批准规则。未获批准时，只做有证据支持的临时口吻匹配。

## 上游Humanizer的三遍顺序
1. **声音发现**：用户本轮直接指定样本和口吻 > 已明确批准的独立档案 > 当前正式文档中该人真实发言 > 保守自然口语。根据文本长度校准置信度；样本很少时不伪装“了解得很深”。
2. **匹配说话分布**：逐人分析句长变化、先接话还是先发问、语气温度、词汇、标点、段落长短、称呼、是否自我纠正、表情频率。不能只靠“49岁会计师”推断家庭预算、职业内幕或具体买入记录。
3. **去掉机械腔调**：参考 [hannsxpeter/humanizer](https://github.com/hannsxpeter/humanizer) 的32种典型模式（浮夸意义、营销口号、讨好、套话、排比、词汇、被动句、格式残留等），仅在确实存在时纠正思想/表达，不生硬做关键词替换。自然原句最小修改。
4. **反向审查**：不改原意、具体数字、股票代码、日期、条件推断；不从历史样本挪用发生在旧日期的交易/经历；不把作者已经确认的幽默或粗粝口语磨平。冲突时反向审查优先。

## 个体维度
- 语言长度：普通社群多0—2句，必要时自然延长；先生/助理可稍长但易听懂；用户指定字数优先。
- 互动动机：今天遇到哪个具体消息，为什么对他有用？可以沉默，不强制全部出场。
- 专业边界：职业会影响其会注意什么问题；会计师、工程师、医生不自动成为持牌证券分析师。
- emoji：参照 `references/member-emoji-guidelines-v2.7.md`，按本人已采用发言与当下情绪使用，允许为零；避免“所有人😂🚀”，不可按每条一个强制配额。
- 跨角色比较：两个成员完全同一句、同节奏重复发问需重写。不能把所有人都写成先生的附和者；允许质疑、调侃、担心、简单寒暄。

## 用户修订学习
用户明确采用并归档的文本才是新历史，关联日期/人物ID/消息来源。由修订归纳的“喜欢短句/更常提问”等为待确认规则，未经用户确认不可加入强制风格；批准后带版本号储存可回滚。ChatGPT不得将本机浏览器LocalStorage说成已进入仓库。
