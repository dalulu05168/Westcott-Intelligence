# v1.4 新闻发布前核验

适用：全球股市重大事件；沿用原5项任务、12节点、65人及视觉V2.0规则。此规则优先于旧文中“因果明确”“按时间顺序三条一批”等可能造成强行归因或凑数的表述。

## 先建事实表，再写播报

每条独立主张分配claim_id，分别记录事实、数字、因果、条件性分析。每条来源记录URL、原始发布者origin_id、正文读取状态、发布时间、实际抓取时间、可定位摘录；动态行情记录观测时间，不能用抓取时间替代。来源不是完整可读正文或官方结构化数据时，搜索摘要、链接、转载只作为候选线索，不能标为完整核验。日期、恢复期限、单位、证券代码、指数全名和报告期属于关键事实；网页不可读不证明事实虚假，但证据补齐前不进入确定性播报。

保留中文原始数字字符串及规范化结果，人工或实际工具复核后记录normalization_reviewed。千分位、罗语小数逗号、正负号、百分比和基点不可混用。每个数字同时记录instrument、unit、basis、market_state、as_of和source_value；价格还须有币种，期货须有合约。来源未明确比较基准时不得猜测涨跌基准；不把Nasdaq Composite当Nasdaq 100，不把竞价指示价当成交或未来开盘价。存在前收基准才计算涨跌率，禁止倒推一个“独立核验的前收”。

## 状态与发布决定

- CONFIRMED：正文或官方数据可读，摘录直接支持对应事实，关键数字、日期及比较口径已核对，无未解冲突。
- PENDING：只见摘要、原文不可读、日期或数字缺证据、口径不明。仅在后台列待核实，不进入资讯助理的确定性事实句。
- CONFLICT：可靠来源冲突未解决。停止相关确定性结论，说明差异和还需核实什么。
- 单一官方来源可证明其直接陈述，不要求两个来源才报道该事实。确证的市场因果解释须两条真正独立可靠证据，不将同一通讯社的多处转载计为独立来源；两条报道仍不自动证明因果，需逐条核对归因范围。
- 仅存在合理传导机制时作为条件性分析，明确“可能/如果/还要看”，并以已确认事实为前提。不要用免责声明给前面的无证据断言兜底。

先从候选中剔除PENDING/CONFLICT主张，再重写安全播报。不能仅删除后台的数字，却在群内保留“已经延长”“导致上涨”等同一无证据结论；标题、成员台词、Jonathan解析及图片都只能引用同一已确认事实集。没有核实事实时不凑新闻：普通雷达静默；N01仍交付后台核验状态与观察清单且不生成成员对白；工作日11:15 N06固定输出午间准备稿，可说明无可核实新增、缺失数据及待观察条件，不被静默规则覆盖。固定节点不得因门禁无可发布事实而声称任务已执行失败。

群内自然口语，钟点HH:mm，重大事件日期保留；夜间不写早上好。先讲发生了什么，再说有证据的市场反馈，最后给带条件的观察方向。默认1–2条重大主线，不凑满条数。旧闻无新增和持续影响证据则退场。缺跨任务历史如实限定去重范围。N01无对白；其他群聊节点仅在正式人物资料可访问时给3–6条虚构候选，65人保持不变，未采用不记为历史。图像保持简约少字多图，不得带入被拦截主张。

## 可执行检查与局限

用scripts/news_release_gate.py检查审核后的证据表。它验证字段、时间、数值对应、涨跌计算及独立来源标识，并从通过的claim_id导出approved_facts；不接收自由拼接的发布正文。它不联网、不鉴别来源真实性、不自动判断摘录含义或真实独立性；不能通过填写CONFIRMED就宣称新闻真实。reviewed_by必须写实际执行核验的人或工具流程，不伪造独立审稿人。生成播报后仍须复核每个事实句与批准事实集的对应，禁止添加新主张。

用法：python scripts/news_release_gate.py path/to/ledger.json --output path/to/result.json。PASS仅代表这份账本的所选事实通过一致性检查；BLOCK禁止发布所选内容；NO_PUBLISHABLE_FACTS按节点职责交付状态或静默。不允许用单元测试通过推导线上准确率。

fixtures/radar-old-ledger.json是2026-10-13旧稿的事后复核样本，非原任务当时执行日志；对应修正选择见radar-repaired-ledger.json。test_news_release_gate.py包含明确标为测试的合成数据，不作为真实新闻。完整验收必须另外取得新版实际正文、任务ID关联和运行时间。仓库脚本未连接ChatGPT Scheduled；线上提示词包仅提供可执行的采编说明，不承诺在线任务运行Python。
